Architecture Comparison: The 3 Ingestion Pathways

As highlighted in the audio discussion, different external partners have different integration capabilities. Our architecture solves this with three distinct ingestion pathways.

01

Pathway 1: Canonical Endpoint

Caller already formats their request to strictly match our native internal entity schema.

POST /api/v1/ingest/canonical
  • No transformation engine pass required
  • Direct JSON schema validation
  • Fastest processing path (< 1ms)
Ideal for: Internal microservices, official mobile apps
02

Pathway 2: In-Payload Mapping

Caller passes the raw payload AND the dynamic field-mapping rules in the same request.

POST /api/v1/ingest/dynamic
  • Body includes data and mapping block
  • Zero pre-configuration needed in database
  • Extreme flexibility for developer API clients
Ideal for: Zapier, Make.com, custom middleware clients
Core Audio Focus
03

Pathway 3: Dynamic Endpoints

Dedicated URLs for platforms that send fixed payloads without mapping capability.

POST /api/v1/webhooks/:endpoint_id
  • User generates endpoint (Shopify, Meta, etc.)
  • Mapping retrieved from database by ID
  • Automatic HMAC security verification
Ideal for: Shopify, Meta Ads, Stripe, WooCommerce
